CoachRoyale — platform architecture (colored flows)

Netflix / Uber–style cues: dark canvas, color = domain (edge vs data vs AI vendor vs egress), stroke width = primary vs secondary path, dashed lines for optional / trust-boundary crossings. Workers AI is shown inside the Cloudflare boundary: it is invoked from the Worker via the AI binding (env.AI.run in apps/api-worker/src/lib/ai.ts), not as a separate public internet service the browser calls. Google / Discord sign-in is supabase.auth.signInWithOAuth in apps/web/src/auth/AuthProvider.tsx — browser starts at Supabase Auth, then follows redirects to the IdP (dashed fuchsia spokes). Official Cloudflare logo (Wikimedia Commons). Source doc: docs/architecture/layered-architecture-aws-aligned.md.

Why this differs from a generic Mermaid box diagram: tier-1 platform teams (Netflix playback vs control paths, Uber mesh + domain-colored RPC diagrams) typically separate control / API from data / async and use weight + hue so reviewers can scan risk in seconds. Here, Workers AI is nested under the same vendor boundary as the Worker because it is a Cloudflare runtime binding, not a third-party box peer to “Cloudflare.” Logo: Wikimedia Commons — Cloudflare_Logo.svg (trademark Cloudflare, Inc.).
